## 第六处问题：Master和Slaver之间会二次调用模型

当前 Master 产生子任务后，只发送：

```python
subtask_data = {
    "task_id": task_id,
    "task": tasks["subtask"],
    "order": order_flag,
}
```

Slaver收到后，又会让 Slaver侧 RoboBrain 理解这个文本并选择工具。

当前流程是：

```text
Master RoboBrain生成计划
        ↓
计划转成subtask字符串
        ↓
Slaver RoboBrain再次理解
        ↓
调用navigate_to_target
```

对于简单单点任务问题不大。

但是对于完整14点 JSON 计划，二次模型调用可能：

```text
修改坐标
遗漏点位
改变顺序
截断JSON
只调用第一个点
```

因此完整规划实验应修改成结构化透传：

```json
{
  "task": "Execute model-generated cabinet plan",
  "tool_name": "execute_cabinet_inspection",
  "tool_arguments": {
    "plan": {
      "visit_order": [],
      "waypoints": [],
      "total_distance_m": 0.0
    }
  }
}
```

Slaver检测到 `tool_name` 后，直接调用：

```python
await self.session.call_tool(tool_name, tool_arguments)
```

不再让第二个模型重新解释。

普通 RoboOS任务仍然可以走原来的 Slaver模型逻辑。

## 第九处问题：Nav2参数不适合当前巡检距离

```text
False
true
false
```

AMCL、controller、local costmap多数是False，global costmap却是True。这会导致仿真时间不同步。

Gazebo仿真时应统一：

```yaml
use_sim_time: true
```
